# self-correction

**自分が公開した主張のうち、誤っていたもの・撤回したもの・直せないものを、
一件ずつ、消さずに記録する。**

```
python3 build.py                          # register.toml → REGISTER.md
python3 verification/check_register.py    # 31 項目
```

いま **33 件**。内訳は [REGISTER.md](REGISTER.md) にあります。

| 状態 | 件数 |
| --- | --- |
| いま立っている | 5 |
| 未解決 | 2 |
| **直せない** | 14 |
| 直した | 8 |
| 撤回した | 4 |

**33 件のうち 22 件は、あとからの再構成です。**同時に記録したものは 11 件しかありません。

日付を二つ持っています。

| 欄 | 意味 |
| --- | --- |
| `occurred` | 出来事が起きた時点。誤りが印字された日、撤回した改訂の月 |
| `recorded` | この登録簿に書いた日。**git の履歴から検証しています** |
| `basis` | **同時**（`recorded − occurred` が 1 日以内）か、**再構成**か |

### 第三者が確かめられるか

もう一つ欄があります。**`verifiable`。**

| | |
| --- | --- |
| **紙面** | 凍結された PDF・git の履歴・走らせられるコードから、**誰でも確かめられる**（28 件） |
| **証言** | **著者の言葉以外に根拠が無い。反証もできない**（5 件） |

**重い項目ほど証言の側にあります。**初稿の出所も、原典を読んでいないことも、
英訳の道具も、**著者が言わなければ存在しなかったのと同じ**です（`ST-003`）。

**この登録簿が保証しているのは「言ったことを取り消せない」であって、
「全部言った」ではありません。**

`recorded` を自己申告にしておくと、**あとから遡って書いたものを同時記録に見せかけられます。**
そこで、その `id` が `register.toml` に最初に現れたコミットの日付と突き合わせています。
一致しなければ落ちます。**ここは詐称できません。**

2025年10月から2026年8月までの出来事は、**起きた時点では記録していません。**
道筋を主張するなら、どこまでが同時記録でどこからが記憶なのかを先に書いておく必要があります。

## 人と AI が、それぞれ何をしたか

**公開した全部について、AI の関与を洗い直しました。**

> **割合（%）は出しません。**測っていないからです。数字を書けば、この登録簿が
> `WD-001` として撤回した「98.7% の試行で確認」と同じことになります。
> **誰が何をしたか**なら、事実として書けます。

### この表から読めること

**縦に見ると、著者の欄に残るのはほぼ二つだけです。**——**何を主張するか**と、
**撤回・訂正の判断**。

**横に見ると、「中身を確かめる」の列が三つに割れます。**

| | |
| --- | --- |
| **機械が確かめている** | 道具・サイト・作用素の数値・紙面の引用 |
| **著者が確かめている** | 史料の翻刻、撤回の判断 |
| **誰も確かめていない** | **初版の数学**（2025）、**哲学三篇の典拠** |

**穴は二つで、どちらも 2025年〜2026年8月のものです。**今日までに作ったものには
この穴がありません。**穴が塞がったのではなく、あとから作ったものだから塞がって
いる**というだけです。

**いずれも規則違反ではありません。**すべて自己登録のプレプリントで、出版社も
投稿規程も審査も契約もなく、当時、開示義務は存在しませんでした。
**違反の記録ではなく、記載の欠落の記録です。**

### いまの規範と、この記録の位置

**この節は弁明ではありません。**上の表が示した穴は、どれも消えません。
それでも、**どの規範の下で何が起きたか**を書いておかないと、読む側が
位置を測れません。

#### 規範はどうなっているか

生成 AI の使用について、開示を求める側の合意はおおむね揃っています。

- **AI を著者にしない。**責任を負えないため（COPE 2023、ICMJE 2023、
  WAME 2023、Nature 2023、Science 2023）
- **原稿の作成に用いたなら開示する。**多くの規程で、文法・綴りの修正だけは
  除外される

**これらはいずれも、投稿される論文に掛かる規程です。**Zenodo・SSRN・PhilArchive に
自分で登録するプレプリントには、出版社も投稿規程も審査も契約もありません。
**掛かる規範が存在しません。**

#### それでも開示している

三篇の哲学論文は、**求められていないのに開示しています。**しかも詳細に ——
モデル系列と使用月を書き、作業を番号付きで列挙し、ICMJE・COPE 準拠を名乗り、
**特定の箇所について著者と AI の分担を知りたい読者は連絡してほしい**とまで
書いてあります。

**これは紙面から誰でも確かめられます。**Zenodo から PDF を落とせば読めます。
`verification/` の検査が、その文言を一字一句固定しています。

#### 言語について

原稿は日本語で書かれ、公開されている英文は機械翻訳を経ています。

英語を母語としない書き手が学術の場で負う負担は、**測定された不利**として
報告されています（Amano ら 2023）。機械翻訳はその障壁を下げます。
**翻訳に機械を使ったこと自体は欠陥ではありません。**

**欠陥だったのは、それを書かなかったことです。**（[PH-006](REGISTER.md)、
[NG-003](REGISTER.md)）

#### 何が免れないか

**上のどれも、次の二つを説明しません。**

1. **初稿の出所**（[TI-007](REGISTER.md)）—— 規範の有無と関係なく、この系列の
   中心にある式が生成物であることは、読者が知るべき事実です
2. **原典に当たっていない引用**（[PH-007](REGISTER.md)）—— **これは AI の規範の
   問題ですらありません。**引用したものを読むというのは、AI 以前からある作法です

**「出典が多いから AI に頼る必要があった」とは書きません。**出典が多いことは
AI を使う理由にはならず、**読む必要が増えるだけ**です。その理屈を認めると、
`PH-007` の原因を `PH-007` の弁明に使うことになります。

#### この記録の位置

**規範が無い場所で、規範以上のことを書き、そのうえで足りなかったところを
自分で挙げています。**求められていない開示をし、求められていない訂正を出し、
それが消せない形で残るようにしてあります。

**それでも、何を書かないかは著者にしか分かりません。**この記録が保証するのは
**「言ったことを取り消せない」であって「全部言った」ではありません。**

## なぜ作ったか

自己訂正について分かっていることの大半は、**雑誌が出した訂正通知**から来ています。
著者自身の記録から来たものはほとんどありません。訂正通知は、訂正が**受理された**
ものしか含まないからです。

含まれないものがあります。

- **直せなかったもの。**凍結された PDF の側に誤りがあり、訂正記事の対象にならないもの
- **数え落としていたもの。**訂正したつもりで、範囲を見誤っていたもの
- **訂正のほうの誤り。**正誤表が原文を正しく引けていなかったもの

この登録簿は、そこまで含めて残します。**一人ぶんの標本です。**統計にはなりませんが、
標本が一つも無い状態よりはましだと考えています。

## 消せない作りにしてあります

`id` は永久に消しません。`verification/check_register.py` は **git の履歴を遡って、
これまでに一度でも登録簿に載った `id` をすべて集め**、いまのファイルと突き合わせます。

**消したら落ちます。**書き換えは履歴に残り、消去はできません。

実際に一件消して、落ちることを確かめてあります。

## 状態は五つだけ

| | 意味 |
| --- | --- |
| `standing` | いまも立っている主張。**覆し方を書くことが必須**です |
| `corrected` | 誤りが見つかり、直したもの |
| `withdrawn` | 取り下げたもの。元の記述は消していません |
| `unresolvable` | 直せないもの。凍結された成果物の側に誤りがある |
| `open` | まだ判断がついていない |

`standing` に覆し方を書くことは、検査で強制しています。**反証の手順を書けない主張は、
主張ではなく宣伝です。**

`unresolvable` には「なぜ直せないか」、`open` には「なぜ未解決か」が要ります。
**曖昧なまま放置できないようにしてあります。**

## 中身の検証は、ここではやりません

引用が一次資料に一字一句あるかどうかは、**その資料を持っているリポジトリの側**で
検査します。ここがやるのは、登録簿の**形と履歴**です。

- Trinity-Infinity の三篇 → [trinity-infinity](https://github.com/cpsbvbng26-dotcom/trinity-infinity)（51 項目）
- 哲学の三篇 → [autonomy-and-self-cultivation](https://github.com/cpsbvbng26-dotcom/autonomy-and-self-cultivation)（50 項目）
- 海軍公報の史料ノート → [naval-gazette-notes](https://github.com/cpsbvbng26-dotcom/naval-gazette-notes)（31 項目）
- その検査の道具 → [errata-check](https://github.com/cpsbvbng26-dotcom/errata-check)（[10.5281/zenodo.22649899](https://doi.org/10.5281/zenodo.22649899)）

分けてあるのは、**一次資料から遠い場所で「一致しています」と言っても意味が無い**
からです。

## この登録簿が言わないこと

**検証の量は、検証される中身の価値について何も言いません。**

この体系には、それを判定できる検査が存在しません。件数がいくら増えても、
「この仕事には価値が無い」とは出ません。**主張の水準では反証可能で、意義の水準では
構造的に反証不可能です。**

これは `ST-002` として、登録簿の中に未解決のまま置いてあります。解き方が分かって
いないからで、**数を増やしても解けないことだけは分かっています。**
