# self-correction

**自分が公開した主張のうち、誤っていたもの・撤回したもの・直せないものを、
一件ずつ、消さずに記録する。**

```
python3 build.py                          # register.toml → REGISTER.md
python3 verification/check_register.py    # 31 項目
```

いま **35 件**。内訳は [REGISTER.md](REGISTER.md) にある。

| 状態 | 件数 |
| --- | --- |
| いま立っている | 5 |
| 未解決 | 2 |
| **直せない** | 14 |
| 直した | 10 |
| 撤回した | 4 |

35 件のうち 22 件は、あとからの再構成である。同時に記録したものは 13 件しかない。

日付を二つ持っている。

| 欄 | 意味 |
| --- | --- |
| `occurred` | 出来事が起きた時点。誤りが印字された日、撤回した改訂の月 |
| `recorded` | この登録簿に書いた日。**git の履歴から検証している** |
| `basis` | **同時**（`recorded − occurred` が 1 日以内）か、**再構成**か |

### 第三者が確かめられるか

もう一つ欄がある。**`verifiable`。**

| | |
| --- | --- |
| **紙面** | 凍結された PDF・git の履歴・走らせられるコードから、**誰でも確かめられる**（28 件） |
| **証言** | **著者の言葉以外に根拠が無い。反証もできない**（5 件） |

重い項目ほど証言の側にある。初稿の出所も、原典を読んでいないことも、英訳の
道具も、著者が言わなければ存在しなかったのと同じである（`ST-003`）。

この登録簿が保証しているのは「言ったことを取り消せない」であって、「全部言った」
ではない。

`recorded` を自己申告にすれば、あとから遡って書いたものを同時記録に見せかけられる。
そこで、その `id` が `register.toml` に最初に現れたコミットの日付と突き合わせている。
一致しなければ落ちる。ここは詐称できない。

2025年10月から2026年8月までの出来事は、起きた時点では記録していない。道筋を
主張するなら、どこまでが同時記録でどこからが記憶なのかを先に書く必要がある。

## 人と AI が、それぞれ何をしたか

公開した全部について、AI の関与を洗い直した。

> 割合（%）は出さない。測っていないからである。数字を書けば、この登録簿が
> `WD-001` として撤回した「98.7% の試行で確認」と同じことになる。
> 誰が何をしたかなら、事実として書ける。

### この表から読めること

縦に見ると、著者の欄に残るのは二つである。何を主張するかと、撤回・訂正の判断。

横に見ると、「中身を確かめる」の列が三つに割れる。

| | |
| --- | --- |
| **機械が確かめている** | 道具・サイト・作用素の数値・紙面の引用 |
| **著者が確かめている** | 史料の翻刻、撤回の判断 |
| **誰も確かめていない** | **初版の数学**（2025）、**哲学三篇の典拠** |

穴は二つ。どちらも 2025年から 2026年8月のものである。今日までに作ったものに
この穴は無い。塞がったのではない。あとから作ったものだから、はじめから無い。

いずれも規則違反ではない。すべて自己登録のプレプリントであり、出版社も投稿規程も
審査も契約もない。当時、開示義務は存在しなかった。違反の記録ではなく、記載の
欠落の記録である。

### いまの規範と、この記録の位置

この節は弁明ではない。上の表が示した穴は消えない。ただし、どの規範の下で
何が起きたかを書かなければ、読む側は位置を測れない。

#### 規範はどうなっているか

生成 AI の使用について、開示を求める側の合意はおおむね揃っている。

- **AI を著者にしない。**責任を負えないため（COPE 2023、ICMJE 2023、
  WAME 2023、Nature 2023、Science 2023）
- **原稿の作成に用いたなら開示する。**多くの規程で、文法・綴りの修正だけは
  除外される

これらはいずれも、投稿される論文に掛かる規程である。Zenodo・SSRN・PhilArchive に
自分で登録するプレプリントには、出版社も投稿規程も審査も契約もない。掛かる規範が
存在しない。

#### それでも開示している

三篇の哲学論文は、求められていないのに開示している。しかも詳細に ―― モデル系列と
使用月を書き、作業を番号付きで列挙し、ICMJE・COPE 準拠を名乗り、特定の箇所に
ついて著者と AI の分担を知りたい読者は連絡してほしいとまで書いてある。

紙面から誰でも確かめられる。Zenodo から PDF を落とせば読める。`verification/` の
検査が、その文言を一字一句固定している。

#### 言語について

原稿は日本語で書かれ、公開されている英文は機械翻訳を経ている。

英語を母語としない書き手が学術の場で負う負担は、測定された不利として報告が
ある（Amano ら 2023）。機械翻訳はその障壁を下げる。翻訳に機械を使ったこと自体は
欠陥ではない。

欠陥は、それを書かなかったことである（[PH-006](REGISTER.md)、
[NG-003](REGISTER.md)）。

#### 何が免れないか

上のどれも、次の二つを説明しない。

1. **初稿の出所**（[TI-007](REGISTER.md)）—— 規範の有無と関係なく、この系列の
   中心にある式が生成物であることは、読者が知るべき事実である
2. **原典に当たっていない引用**（[PH-007](REGISTER.md)）—— **これは AI の規範の
   問題であるらない。**引用したものを読むというのは、AI 以前からある作法である

「出典が多いから AI に頼る必要があった」とは書かない。出典が多いことは AI を
使う理由にならない。読む必要が増えるだけである。その理屈を認めれば、`PH-007` の
原因を `PH-007` の弁明に使うことになる。

#### この記録の位置

規範が無い場所で、規範以上のことを書き、足りなかったところを自分で挙げている。
求められていない開示をし、求められていない訂正を出し、それが消せない形で残る
ようにしてある。

それでも、何を書かないかは著者にしか分からない。この記録が保証するのは
「言ったことを取り消せない」であって、「全部言った」ではない。

## なぜ作ったか

自己訂正について分かっていることの大半は、**雑誌が出した訂正通知**から来ている。
著者自身の記録から来たものはほとんどない。訂正通知は、訂正が**受理された**
ものしか含まないからである。

含まれないものがある。

- **直せなかったもの。**凍結された PDF の側に誤りがあり、訂正記事の対象にならないもの
- **数え落としていたもの。**訂正したつもりで、範囲を見誤っていたもの
- **訂正のほうの誤り。**正誤表が原文を正しく引けていなかったもの

この登録簿は、そこまで含めて残す。**一人ぶんの標本である。**統計にはならないが、
標本が一つも無い状態よりはましだと考えている。

## 消せない作りにしてある

`id` は永久に消しない。`verification/check_register.py` は **git の履歴を遡って、
これまでに一度でも登録簿に載った `id` をすべて集め**、いまのファイルと突き合わせる。

**消したら落ちる。**書き換えは履歴に残り、消去はできない。

実際に一件消して、落ちることを確かめてある。

## 状態は五つだけ

| | 意味 |
| --- | --- |
| `standing` | いまも立っている主張。**覆し方を書くことが必須**である |
| `corrected` | 誤りが見つかり、直したもの |
| `withdrawn` | 取り下げたもの。元の記述は消していない |
| `unresolvable` | 直せないもの。凍結された成果物の側に誤りがある |
| `open` | まだ判断がついていない |

`standing` に覆し方を書くことは、検査で強制している。**反証の手順を書けない主張は、
主張ではなく宣伝である。**

`unresolvable` には「なぜ直せないか」、`open` には「なぜ未解決か」が要る。
**曖昧なまま放置できないようにしてある。**

## 中身の検証は、ここではやらない

引用が一次資料に一字一句あるかどうかは、**その資料を持っているリポジトリの側**で
検査する。ここがやるのは、登録簿の**形と履歴**である。

- Trinity-Infinity の三篇 → [trinity-infinity](https://github.com/cpsbvbng26-dotcom/trinity-infinity)（76 項目）
- 哲学の三篇 → [autonomy-and-self-cultivation](https://github.com/cpsbvbng26-dotcom/autonomy-and-self-cultivation)（50 項目）
- 海軍公報の史料ノート → [naval-gazette-notes](https://github.com/cpsbvbng26-dotcom/naval-gazette-notes)（31 項目）
- その検査の道具 → [errata-check](https://github.com/cpsbvbng26-dotcom/errata-check)（[10.5281/zenodo.22649899](https://doi.org/10.5281/zenodo.22649899)）

分けてあるのは、**一次資料から遠い場所で「一致している」と言っても意味が無い**
からである。

## この登録簿が言わないこと

**検証の量は、検証される中身の価値について何も言わない。**

この体系には、それを判定できる検査が存在しない。件数がいくら増えても、
「この仕事には価値が無い」とは出ない。**主張の水準では反証可能で、意義の水準では
構造的に反証不可能である。**

これは `ST-002` として、登録簿の中に未解決のまま置いてある。解き方が分かって
いないからで、**数を増やしても解けないことだけは分かっている。**
