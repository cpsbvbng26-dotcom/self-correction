# self-correction

**自分が公開した主張のうち、誤っていたもの・撤回したもの・直せないものを、
一件ずつ、消さずに記録する。**

```
python3 build.py                          # register.toml → REGISTER.md
python3 verification/check_register.py    # 29 項目
```

いま **30 件**。内訳は [REGISTER.md](REGISTER.md) にあります。

| 状態 | 件数 |
| --- | --- |
| いま立っている | 5 |
| 未解決 | 1 |
| **直せない** | 13 |
| 直した | 7 |
| 撤回した | 4 |

**30 件のうち 21 件は、あとからの再構成です。**同時に記録したものは 9 件しかありません。

日付を二つ持っています。

| 欄 | 意味 |
| --- | --- |
| `occurred` | 出来事が起きた時点。誤りが印字された日、撤回した改訂の月 |
| `recorded` | この登録簿に書いた日。**git の履歴から検証しています** |
| `basis` | **同時**（`recorded − occurred` が 1 日以内）か、**再構成**か |

`recorded` を自己申告にしておくと、**あとから遡って書いたものを同時記録に見せかけられます。**
そこで、その `id` が `register.toml` に最初に現れたコミットの日付と突き合わせています。
一致しなければ落ちます。**ここは詐称できません。**

2025年10月から2026年8月までの出来事は、**起きた時点では記録していません。**
道筋を主張するなら、どこまでが同時記録でどこからが記憶なのかを先に書いておく必要があります。

**公開した全部について、AI の関与を洗い直しました。**紙面の開示文がどこまで
述べているかも含めて、一覧にしてあります。

| 成果物 | 著者が持っていたもの | AI がしたこと | 紙面の開示 |

| **哲学三篇** | **主張。日本語まで** | **英訳と、引用の割り当て** | 英訳は**無い** → [PH-006](REGISTER.md)<br>引用は二本で開示済み。原典未確認は**無い** → [PH-007](REGISTER.md) |
| **海軍公報のノート** | 史料の選択・翻刻・論旨 | **史料に書かれていることの英訳だけ** | **無い**（構成と推敲のみ）→ [NG-003](REGISTER.md) |

**下へ行くほど範囲が狭くなります。**海軍公報のノートが最も狭く、
Trinity-Infinity が最も広い —— **中心にある式そのものが生成物**です。

**いずれも規則違反ではありません。**すべて自己登録のプレプリントで、出版社も
投稿規程も審査も契約もなく、当時、開示義務は存在しませんでした。
**違反の記録ではなく、記載の欠落の記録です。**

## なぜ作ったか

自己訂正について分かっていることの大半は、**雑誌が出した訂正通知**から来ています。
著者自身の記録から来たものはほとんどありません。訂正通知は、訂正が**受理された**
ものしか含まないからです。

含まれないものがあります。

- **直せなかったもの。**凍結された PDF の側に誤りがあり、訂正記事の対象にならないもの
- **数え落としていたもの。**訂正したつもりで、範囲を見誤っていたもの
- **訂正のほうの誤り。**正誤表が原文を正しく引けていなかったもの

この登録簿は、そこまで含めて残します。**一人ぶんの標本です。**統計にはなりませんが、
標本が一つも無い状態よりはましだと考えています。

## 消せない作りにしてあります

`id` は永久に消しません。`verification/check_register.py` は **git の履歴を遡って、
これまでに一度でも登録簿に載った `id` をすべて集め**、いまのファイルと突き合わせます。

**消したら落ちます。**書き換えは履歴に残り、消去はできません。

実際に一件消して、落ちることを確かめてあります。

## 状態は五つだけ

| | 意味 |
| --- | --- |
| `standing` | いまも立っている主張。**覆し方を書くことが必須**です |
| `corrected` | 誤りが見つかり、直したもの |
| `withdrawn` | 取り下げたもの。元の記述は消していません |
| `unresolvable` | 直せないもの。凍結された成果物の側に誤りがある |
| `open` | まだ判断がついていない |

`standing` に覆し方を書くことは、検査で強制しています。**反証の手順を書けない主張は、
主張ではなく宣伝です。**

`unresolvable` には「なぜ直せないか」、`open` には「なぜ未解決か」が要ります。
**曖昧なまま放置できないようにしてあります。**

## 中身の検証は、ここではやりません

引用が一次資料に一字一句あるかどうかは、**その資料を持っているリポジトリの側**で
検査します。ここがやるのは、登録簿の**形と履歴**です。

- Trinity-Infinity の三篇 → [trinity-infinity](https://github.com/cpsbvbng26-dotcom/trinity-infinity)（51 項目）
- 哲学の三篇 → [autonomy-and-self-cultivation](https://github.com/cpsbvbng26-dotcom/autonomy-and-self-cultivation)（50 項目）
- 海軍公報の史料ノート → [naval-gazette-notes](https://github.com/cpsbvbng26-dotcom/naval-gazette-notes)（31 項目）
- その検査の道具 → [errata-check](https://github.com/cpsbvbng26-dotcom/errata-check)（[10.5281/zenodo.22649899](https://doi.org/10.5281/zenodo.22649899)）

分けてあるのは、**一次資料から遠い場所で「一致しています」と言っても意味が無い**
からです。

## この登録簿が言わないこと

**検証の量は、検証される中身の価値について何も言いません。**

この体系には、それを判定できる検査が存在しません。件数がいくら増えても、
「この仕事には価値が無い」とは出ません。**主張の水準では反証可能で、意義の水準では
構造的に反証不可能です。**

これは `ST-002` として、登録簿の中に未解決のまま置いてあります。解き方が分かって
いないからで、**数を増やしても解けないことだけは分かっています。**
